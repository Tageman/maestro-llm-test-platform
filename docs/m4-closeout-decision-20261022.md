# 一期剩余项必要性与收尾裁决（2026-10-22）

## 结论

当前代码可以提交、推送作为一期候选检查点；**不建议直接宣布包含无人值守自动修复的一期正式验收完成**。剩余事项应收敛为少量正确性修复、受影响路径回归及已有走查/签署材料核验，不继续扩展二期能力。推送不等于创建正式 release/tag，也不代替产品/测试签名。

已有成果：跨 Case Fixture、退出恢复和交付链已实现；最新后端 313 项测试通过、核心纯逻辑分支覆盖 90.94%；历史五阶段真实模拟器退出验收通过。完整来源见 `m4-evidence-matrix-20261022.md`。这些结果不是新发现缺口已经被覆盖的证明。

## MCP 风险复现与边界

本次只使用临时目录和模拟 MCP 客户端，没有连接或控制真实设备，没有改业务 YAML：

1. 请求目标 `emulator-5554`，设备响应仅含 `emulator-55540`，当前检查没有拒绝。
2. 截图响应标为 image，但数据是 `base64("not an image")`；当前诊断服务将其保存为截图并仍返回页面层级中的唯一候选。

这证明门禁不严，不证明真实设备已经发生误操作：`inspect_screen` / `take_screenshot` 仍显式传入原目标 ID，真实服务可能拒绝不存在目标；修复候选由层级提取，截图当前不参与候选选择。因此不夸大为“必定操作错设备”或“截图坏就必然修复错”。但它们违背现有“绑定同一设备、层级和截图证据齐全”的自动修复承诺，属于功能正确性与证据可信度问题，而不是新增需求。

## 收尾边界

建议保留已约定的一期自动修复范围，只关闭以上两项小范围缺口及对应回归、材料核验。若希望立即以当前版本结束，需要另行明确把自动修复降为实验功能或禁用，并书面确认验收范围/风险调整；本次推送不会擅自变更功能承诺，也不会把仍未满足的门禁写成 ACCEPTED。
